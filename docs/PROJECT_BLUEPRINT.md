## 1. Executive Summary & Design System Clarification

VibeLens is an autonomous codebase hygiene, vulnerability reachability, and architecture visualization system built specifically for the generative AI coding era. Operating 100% locally on developer machines without uploading source code to third-party clouds, it solves the catastrophic code bloat, context poisoning, and CVE alert fatigue introduced by rapid vibe coding in Cursor, Claude Code, v0, and Bolt.

### 1.1 Clarification: The "CrashLens" Design System
Throughout this project, references to **"CrashLens"** refer strictly to our internal, open-source high-craft telemetry design framework (as showcased in our prior production deployment at `orcathon-2026.vercel.app`). CrashLens embodies an industrial-grade, dark-mode CAD radar aesthetic: pitch-black obsidian backgrounds (`#09090b`), CAD blueprint crosshairs, monospace telemetry chips (`[STATUS: ACTIVE // 12ms]`), and tactile glassmorphic borders (`border-white/10`). VibeLens uses this design system for its own interface and provides an automated compiler to refactor generic AI frontends into this same production aesthetic.

## 2. The Problem Statement (In Plain English)

Developers are generating entire software systems via natural language prompts. However, within 24 to 48 hours of rapid prompting, codebases experience five distinct systemic breakdowns:

1. **Problem 1: Slop & Phantom Duplication:** Because the AI lacks persistent memory of previous sessions, it constantly hallucinates duplicate utility functions across folders (e.g. four conflicting date/string parsers), leaves dead components, and abandons unused npm packages.
2. **Problem 2: Context Window Poisoning & Token Burn:** Every Cursor or Claude prompt requires passing project files into the model's context window. Bloated duplicate code and dead files increase prompt token consumption by 35% to 50%, multiplying API costs and triggering model hallucinations.
3. **Problem 3: CVE Alert Fatigue & False Alarms:** Traditional scanners (Dependabot, Snyk, npm audit) flood developer inboxes with dozens of critical CVE alerts. In over 80% of cases, the vulnerability is in dead, uncalled code inside the package. Developers suffer alert fatigue and end up ignoring real threats.
4. **Problem 4: Generic "AI Slop" Frontends:** Every frontend generated by AI looks identical: flat white cards, pastel purple gradients, and chaotic div-soup with 45 Tailwind utility classes per element.
5. **Problem 5: The "Black-Box Terror":** Because the developer did not write the 80 sprawling files, they cannot visualize what depends on what. Teams are terrified to delete or refactor anything because they have zero visibility into what will break.
6. **Problem 6: Cross-Agent Context Loss & New Chat Amnesia:** Developers constantly switch between coding environments (e.g. Claude Code in CLI ↔ Cursor IDE ↔ Windsurf) or start fresh chat sessions. Because context is severed, the new agent forgets existing utilities and architectural invariants, hallucinating duplicate helpers and violating codebase rules. Naively dragging 40+ raw files into the prompt consumes 48,000+ tokens ($0.48/prompt), slowing responses and triggering severe model hallucinations.

## 4. Technical Architecture: Modern TS/React Stack

* **Frontend & 3D Spatial Canvas:** Next.js 15 (App Router), React 19, TypeScript. 3D WebGL galaxy rendered via Three.js with `@react-three/fiber` and `@react-three/drei`. Styled using Tailwind CSS v4, `shadcn/ui` (Radix React primitives), and CrashLens industrial telemetry tokens.
* **Authentication & Dev Keys:** Clerk handles developer sign-in, GitHub OAuth identity verification, organization workspace boundaries, and issuing secure API keys/tokens for the local CLI and Cursor MCP server.
* **Database & Persistence:** Supabase provides the managed PostgreSQL relational database, storing audited repository metadata, CVE reachability scan histories, team vulnerability registries, and verifiable token-saving logs.
* **Type-Safe ORM:** Drizzle ORM defines TypeScript schemas with zero runtime overhead, executing type-safe queries against Supabase PostgreSQL for repository audits, AST scan records, and vulnerability state machines.
* **Edge Cache & High-Speed Telemetry:** Upstash Redis acts as the serverless edge memory tier: caching parsed OSV/NVD CVE database lookups (sub-5ms retrieval), storing 1Hz streaming telemetry vector clocks for the 3D topology radar, and rate-limiting incoming MCP requests.
* **AST & Static Analysis Engine:** `@babel/parser` and `@babel/traverse` for zero-overhead JavaScript and TypeScript Abstract Syntax Tree decomposition, coupled with `es-module-lexer` for rapid import/export resolution.
* **Model Context Protocol (MCP) Server:** Official `@modelcontextprotocol/sdk` for Node.js over stdio and JSON-RPC, enabling Cursor and Claude Code to invoke native pre-prompt prevention tools.
* **Local CLI Sentinel & Test Harness Gate:** Node.js daemon built with `commander` and `chokidar` for 1Hz file watching. Automated child-process execution runs local test suites (`npm test` / `vitest`) before calling `@octokit/rest` for GitHub PR generation.

## 5. The ReachableSec 4-Tier Confidence Model

In enterprise security, wrongly silencing an active vulnerability is catastrophic. Because static analysis cannot deterministically trace dynamic code evaluation (such as `eval()`, dynamic `require()`, or runtime reflection), ReachableSec introduces an honest, four-tier confidence classification:

* **Tier 1: REACHABLE (Verified Attack Path):** 100% verified static execution path from an exposed HTTP/API entry point down to the vulnerable package method. Highlighted in alarming neon red with automated patch PR.
* **Tier 2: LIKELY (Indirect / Conditional Path):** Call path exists through internal event emitters, callbacks, or conditional branches. Marked in orange, alerting developers to review.
* **Tier 3: UNKNOWN (Dynamic Reflection Boundary):** Dynamic `require(variable)`, `eval()`, or reflection detected along the path. Statically unprovable. Honestly flagged as "Unknown"—never silently dismissed.
* **Tier 4: UNREACHABLE (Verified Dead Code):** Mathematical proof of zero execution path from any application entry point. Stamped as `[SILENCED // DEAD CODE]`, eliminating 88% of alert noise.

## 6. Dual Prevention Engine: Native MCP Server & CLI Sentinel

### 6.1 Native Model Context Protocol (MCP) Server
Running via standard JSON-RPC over stdio, VibeLens registers two native tools directly with Cursor and Claude Code:
1. `find_existing_utility({ purpose, keywords })`: Before writing a new helper function, the AI agent calls this tool. VibeLens searches the AST vector registry. If a utility like `formatDate()` already exists, VibeLens returns the canonical import path, stopping the AI from generating a duplicate.
2. `check_package({ packageName, intendedFunction })`: Before the AI agent runs `npm install`, it queries VibeLens. VibeLens checks the OSV database. If the package contains high-severity vulnerabilities in the requested function, the AI is advised to select a secure alternative.

### 6.2 Local CLI Sentinel (`vibelens watch`)
For manual edits or non-MCP workflows, running `npx vibelens watch` monitors AST diffs at 1Hz. The moment an unneeded package or duplicate helper is saved, an instant terminal prompt triggers with one-key auto-resolution:
```bash
[VibeLens Sentinel] ⚠️ SLOP DETECTED in src/components/Card.tsx
-> Cursor just hallucinated a duplicate 'formatDate' helper.
-> Found existing canonical utility in src/utils/date.ts.
-> Press [Y] to auto-link existing function and cancel duplication.
```

### 6.3 Zero-Token ContextRelay (Cross-Agent Context Handover Engine)
When developers switch between coding environments (e.g. Claude Code CLI ↔ Cursor IDE ↔ Windsurf) or start a fresh chat session, context is severed. Naively dumping 40+ project files into the prompt consumes 48,200+ tokens ($0.48/prompt) and induces model confusion.

ContextRelay solves this by maintaining a deterministic, machine-readable **AST State Snapshot** (`.vibelens/handover.json`) that captures the essential project state in just **~380 tokens (99.2% token savings)**:
```json
{
  "vibelens_version": "1.0.0",
  "project": "vibelens-core",
  "canonical_utilities": {
    "formatDate": "src/utils/date.ts#L12",
    "apiFetch": "src/lib/api/client.ts#L4",
    "cn": "src/lib/utils/styles.ts#L8"
  },
  "architectural_invariants": {
    "theme": "obsidian_cad (#060608)",
    "stack": "Next.js 15 + React 19 + Tailwind v4 + Radix",
    "strict_rules": [
      "100% JS/TS ecosystem only (no Python/Rust binaries)",
      "Never upload raw code to cloud servers",
      "Dynamic require() must be classified as 'Unknown'"
    ]
  },
  "blast_radius_locks": ["src/core/auth/session.ts (CRITICAL: 14 callers)"],
  "last_session_diff": {
    "modified": ["src/sast/reachability.ts"],
    "next_intent": "Connect reachability AST to 3D WebGL laser shader"
  }
}
```

**Ingestion Mechanisms:**
1. **MCP Tool Handshake (`vibelens_get_handover`):** Cursor and Claude Code query this tool on initialization (consuming 0 prompt tokens).
2. **Deterministic Instruction Guard (`.cursorrules` / `.claude.md`):** Agents are instructed to read `.vibelens/handover.json` before creating new helper functions, preventing duplication at the source across all agent switches.

## 7. The Blast Radius Inspector (Solving The Black-Box Terror)

Problem #5 is solved through bidirectional DAG traversal. Selecting any file or function in the 3D WebGL galaxy opens the Blast Radius HUD:
* **Upstream Impact (What Breaks):** Instantly highlights every route, component, and hook that calls the selected function. If you delete or alter this file, VibeLens lists the exact files that will fail.
* **Downstream Dependencies (What It Needs):** Lists all imported npm packages and internal sub-utilities required to execute the node.

## 8. The Safety Net: Automated Test-Suite Verification

Unattended automated refactoring destroys developer trust if it breaks working code. VibeLens enforces a strict safety net before any Pull Request is created:
1. **Step 1: Visual Semantic Diff:** The dashboard renders a unified diff preview showing exact consolidations and import rewrites.
2. **Step 2: Automated Local Test Runner:** VibeLens spawns a child process executing the repository's native test suite (`npm test`, `vitest`, or `jest`).
3. **Step 3: Gated GitHub Pull Request:** Only if 100% of existing unit and integration tests pass green does VibeLens invoke `@octokit/rest` to open the Pull Request. If tests fail, the refactor is cleanly aborted with a detailed diagnostic log.

## 11. Known Limitations & Technical Honesty

* **Ecosystem Scope in v1:** Static AST parsing and reachability call-graph construction currently support JavaScript and TypeScript ecosystems. Python and Go are scheduled for Phase 3.
* **Dynamic Reflection Boundaries:** Runtime dynamic evaluations (e.g. `eval()`, `vm.runInContext()`, dynamic computed `require()`) cannot be statically verified. VibeLens honestly categorizes these as 'Unknown' rather than claiming false reachability proofs.
* **Single-Repo AST Scope:** Cross-repository microservice RPC traces are not resolved in the local CLI; analysis is bounded to the active application repository.
